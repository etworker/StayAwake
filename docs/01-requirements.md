# 01 需求

## 背景

笔记本 / 台式机在「无人操作」一段时间后会被系统判定为空闲，进而熄屏、锁屏甚至睡眠。某些场景（演示、监控大屏、长时间编译/下载、远程桌面保持会话）需要机器在这些场景下**保持可用**，而系统并未提供便捷的全局开关。

StayAwake 是一个常驻**托盘**的小工具：以「模拟活动 + 系统电源断言」的方式阻止空闲睡眠，用户随时可以通过托盘菜单暂停。

## 目标

- 一个可执行文件（或 .app 包），无需安装、无需后台服务即可运行；
- 覆盖 Windows / Linux / macOS 三平台，交互与文案保持一致；
- 对用户**透明可控**：随时暂停/恢复，所有设置即时生效并可持久化。

## 功能性需求

| 编号 | 需求 | 说明 |
| ---- | ---- | ---- |
| FR-1 | 阻止空闲睡眠 | 启动后默认激活；睡眠 / 熄屏 / 锁屏的「空闲」触发被抑制 |
| FR-2 | 鼠标微动兜底 | 每 60 秒移动鼠标 1 像素并复位，作为电源断言之外的保险 |
| FR-3 | 托盘图标与状态 | 睁眼（激活）/ 闭眼（暂停）直观反映当前状态 |
| FR-4 | 托盘菜单 | 保持清醒开关、合盖行为（支持的平台）、开机自启、语言、关于、退出 |
| FR-5 | 暂停立即生效 | 暂停后系统恢复自然睡眠策略，不允许残留抑制（Windows 断言按线程生效，需显式唤醒清理） |
| FR-6 | 开机自启 | 三平台各自的原生机制，可随时开关并真实反映状态 |
| FR-7 | 合盖行为（接电源时） | Linux 与 macOS（Apple Silicon）提供「插电合盖不动作 / 睡眠」切换；电池合盖始终维持系统默认 |
| FR-8 | 界面语言 | 简体中文 / 英文，可跟随系统，切换即时生效并持久化 |
| FR-9 | 单实例 | 同一用户重复启动静默退出；不同用户互不影响 |
| FR-10 | 状态持久化 | 语言、合盖模式写入用户配置目录，跨会话保留 |

## 非功能性需求

- **零依赖运行**：预编译产物不要求安装运行库（Linux 仅依赖桌面标配的 GTK2/X11）；
- **无控制台窗口**：Windows 下为 GUI 子系统程序，所有操作不弹终端；
- **小体积**：发布二进制剥离符号（见 05-build），单平台产物 ≤ 2.5 MB；
- **免 root / 免管理员**：全部功能以普通用户权限实现，不做需要提权的修改；
- **一致性**：三平台菜单结构、文案、行为一致；差异点（平台不支持的特性）直接不出现对应菜单项。

## 非目标（明确不做）

- 不阻止**显式**电源动作（开始菜单睡眠、电源键）；
- 不管理屏幕保护程序配置；
- 不提供图形化设置窗口——全部交互经托盘菜单完成；
- 不引入跨平台 UI 框架（Lazarus LCL 等），保持各平台原生外观。

## 约束与限制

| 平台 | 限制 |
| ---- | ---- |
| Windows | 合盖行为的系统策略修改需要管理员且常被管控机隐藏，故不提供合盖菜单（详见 02-design） |
| macOS | 合盖守卫依赖 `PreventSystemSleep` 断言，仅 Apple Silicon 实际生效；Intel 上该断言对合盖无效（SMC 平台层强制睡眠，用户态无法否决） |
| Linux | 合盖守卫需要先安装 `src/linux/lid-guard/` 的用户级 systemd 服务（`install.sh`，免 sudo） |
| 全平台 | 只能阻止「空闲导致」的睡眠；合盖在未启用守卫时按系统默认处理 |
